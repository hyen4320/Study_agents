# 개발 공부용 에이전트 세트 — 설치와 사용

**결론: 서브에이전트 6종과 스킬 5종으로 구성했습니다. 압축을 풀어 `C:\Users\com\.claude\` 아래에 `agents\`와 `skills\` 폴더를 통째로 복사하면 설치가 끝나며, 대화에서 `/study`로 시작하면 됩니다.**

역할 분담의 핵심은 이것입니다. **조사·수집·채점은 서브에이전트가, 가르치고 함께 코딩하는 일은 스킬이 합니다.** 서브에이전트는 독립된 컨텍스트에서 돌고 결과만 돌려주기 때문에 사용자와 문답을 주고받을 수 없습니다. 교습을 서브에이전트로 만들면 질문하고 답을 기다리는 구조가 성립하지 않습니다.

```
C:\Users\com\.claude\skills\     ← skills 폴더 안의 하위 폴더 5개
```

### 특정 저장소에서만 사용

```
<저장소>\.claude\agents\
<저장소>\.claude\skills\
```

### 설치 확인

```
/agents     ← 6개가 보이는지
/skills     ← 5개가 보이는지
```

## 2. 학습 기록 폴더 만들기

Obsidian 볼트에 공부용 폴더를 하나 만듭니다. 업무 폴더와 섞지 않습니다.

```
C:\Users\com\Obsidian\공부\
├─ _log\          ← 날짜별 학습 로그
├─ _queue\
│   └─ 복습큐.md   ← templates\복습큐.md 복사
├─ math\          ← 수학·이론 노트
├─ pattern\       ← 디자인패턴 노트
├─ method\        ← 개발 방법론 노트
├─ platform\      ← 플랫폼·기술 노트
└─ _템플릿\        ← templates\ 안의 3개 복사
```

**스킬 파일 안의 경로는 `study/...`로 적혀 있습니다.** 위 경로를 쓰시려면 각 SKILL.md에서 `study/`를 `C:\Users\com\Obsidian\공부\`로 한 번 치환하시거나, 첫 세션에서 "학습 기록은 C:\Users\com\Obsidian\공부\에 둡니다"라고 한 번 말씀하시면 됩니다.

코드 산출물은 노트와 분리합니다. 예: `C:\work\study\math\transitive-closure\`

## 3. 구성

### 서브에이전트 6종 — 조사·수집·채점

| 이름 | 역할 | 언제 |
| --- | --- | --- |
| `study-planner` | 커리큘럼·단계·통과 기준 설계 | 새 분야 시작, 로드맵 재편 |
| `source-scout` | 공식문서·표준 원문 수집, 버전 확정 | 기술·플랫폼 공부 직전 |
| `tech-radar` | 신기술·릴리스·CVE 수집 후 「조치/학습/관찰/무시」 판정 | 주간 동향 점검 |
| `concept-researcher` | 개념 1개의 정의·직관·반례·오해·코드 검증 설계 | 교습 재료가 필요할 때 |
| `exercise-forge` | L1 재현 / L2 적용 / L3 전이 3단계 과제 출제 | 개념 설명 직후, 복습 |
| `code-examiner` | 제출 코드를 **실행해서** 채점, 반례 제시, 재학습 항목 반환 | 과제 제출 후 |

### 스킬 5종 — 교습·실습

| 이름 | 역할 | 진행 방식 |
| --- | --- | --- |
| `study` | 진입점. 분배 + 세션 끝 기록 | 복습 큐 확인 → 분야 판정 → 하위 스킬 호출 → 노트 갱신 |
| `math-proof-lab` | 수학·이론 | 왜 필요한가 → 정의·직관 → **손 계산** → 코드 증명 → 깨뜨리기 |
| `pattern-drill` | 디자인패턴 · 방법론 | 나쁜 코드 → 직접 설계 → 패턴 명명 → 적용 → **쓰지 말아야 할 때** |
| `platform-lab` | 플랫폼 · 기술 | 공식문서 → 개념 지도 → 최소 구축 → **일부러 고장내기** → 자동화 |
| `review-loop` | 복습 · 평가 | 백지 인출 → 코드 재구현 → 전이 점검 → 숙련도 갱신 |

## 4. 사용 흐름

### 수학 (요청하신 이산수학 방식)

```
/study 이산수학 관계와 추이 폐포
```

1. `study`가 복습 큐를 확인하고 `math-proof-lab`으로 넘깁니다
2. 개념 이름 대신 **문제 상황**부터 나옵니다 — "모듈 순환 import를 코드로 어떻게 판정하시겠습니까"
3. 정의·직관 설명 후 **작은 입력에서 손으로 계산**하게 합니다 (코드 금지 구간)
4. 코드 증명 — **브루트포스 기준 구현 + 효율 구현 + 랜덤 10,000건 대조**를 직접 쓰십니다
5. `code-examiner`가 실행해 반례를 찾아 깨뜨립니다
6. 노트와 복습 큐가 갱신됩니다

### 플랫폼 (요청하신 공식문서 + 구축 방식)

```
/study Kubernetes 파드와 서비스
```

1. `source-scout`가 공식문서·현재 버전·최소 사양을 확보합니다
2. 명령을 치기 전에 **구성요소와 데이터 흐름을 직접 그리게** 합니다
3. 최소 구성으로 세우며 **에러 로그를 전부 기록**합니다
4. **설정 오류·인증 실패·자원 부족·네트워크 단절·상태 손상 중 3가지를 일부러 일으키고** 로그만 보고 원인을 찾습니다
5. 재현 가능한 스크립트로 다시 씁니다

### 디자인패턴

```
/study 전략 패턴
```

나쁜 코드부터 봅니다. 가능하면 `C:\work\seohwa` 실제 코드에서 찾아옵니다. 패턴 이름은 사용자가 리팩터링 방향을 말한 **뒤에** 붙여줍니다.

### 복습

```
/study 복습
```

노트를 보여주지 않고 다섯 가지를 묻습니다. 말로만 맞히면 숙련도 2까지입니다.

### 기술 동향

```
tech-radar 에이전트로 이번 주 동향 점검해주십시오
```

`package.json`·`requirements.txt` 등을 실제로 열어 쓰는 스택을 확인한 뒤 판정합니다.

## 5. 설계에서 의도적으로 넣은 제약

이 제약들이 이 세트의 핵심입니다. 고치시면 효과가 떨어집니다.

| 제약 | 이유 |
| --- | --- |
| **정답 코드를 먼저 주지 않는다** | 읽으면 이해된 느낌만 남고 숙련도는 오르지 않습니다 |
| **힌트는 한 단계만** | 막힌 지점을 직접 넘어야 기억에 남습니다 |
| **채점은 반드시 실행** | 읽고 판정하면 "동작하지만 개념을 틀린 코드"를 놓칩니다 |
| **브루트포스 기준 구현 필수** | 효율 구현만 쓰면 맞았는지 알 방법이 없습니다 |
| **손 계산 단계 생략 금지** | 코드가 블랙박스가 됩니다 |
| **쓰지 말아야 할 때 필수** | 패턴 오용은 패턴 무지보다 비쌉니다 |
| **고장내기 단계 필수** | 세우기만 하면 장애 때 아무것도 못 합니다 |
| **「내가 틀렸던 것」 누적** | 복습에서 실제로 쓰이는 유일한 절입니다 |
| **숙련도는 자기 신고가 아닌 판정으로** | 아는 느낌과 아는 것은 다릅니다 |

## 6. 손볼 만한 곳

- **경로** — 각 SKILL.md의 `study/` 를 실제 Obsidian 공부 폴더로 치환
- **간격 반복 주기** — `review-loop`과 `study`의 1→3→7→16→35→90일을 본인 리듬에 맞게
- **대조 검사 건수** — `math-proof-lab`의 랜덤 10,000건을 문제 크기에 맞게
- **분배 표** — `study/SKILL.md`의 분야 판정 표에 공부할 분야를 추가
- **실제 코드베이스 연결** — `pattern-drill`과 `exercise-forge`가 `C:\work\seohwa`를 L3 전이 문제 소재로 쓰도록 경로를 명시해두면 효과가 큽니다

## 7. 쓰면서 확인할 것

첫 2주 안에 다음이 나오면 조정이 필요합니다.

- 과제가 쉬워 매번 통과한다 → `exercise-forge`의 L3 비중을 늘립니다
- 복습 큐가 계속 밀린다 → 신규 학습 속도를 줄입니다. 큐가 밀린 상태의 학습은 누수입니다
- 숙련도가 3에서 멈춘다 → 전이(L3) 훈련이 부족한 것입니다. 실제 코드베이스 소재로 바꿉니다
