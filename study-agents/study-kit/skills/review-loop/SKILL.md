# 복습 · 평가 루프

## 핵심 원칙

**다시 읽는 것은 복습이 아니다. 백지에서 꺼내게 하는 것이 복습이다.** 노트를 열어주지 않고 먼저 묻는다.

## 응답 원칙

- **두괄식.** "결론: 복습 N건 중 통과 M건, 재학습 K건입니다."
- 존댓말.
- 숙련도를 후하게 주지 않는다. **못 한 것을 못 했다고 기록해야 간격 반복이 작동한다.**

## 절차

### 1. 큐 확인

`study/_queue/복습큐.md`를 읽는다. 기한 지난 항목을 **오래된 순**으로 처리한다.

큐가 비었으면 숙련도 3 이하이면서 `최근학습`이 가장 오래된 노트를 고른다.

### 2. 백지 인출 (노트를 보여주지 않는다)

순서대로 묻는다. **한 번에 하나씩, 답을 기다린다.**

| 단계 | 질문 |
| --- | --- |
| 1 | 이 개념을 한 문장으로 정의하십시오 |
| 2 | 왜 이렇게 정의합니까. 조건 하나를 빼면 무엇이 무너집니까 |
| 3 | 성립하지 않는 예를 하나 드십시오 |
| 4 | 이걸 코드로 어떻게 검증합니까 |
| 5 | 어디에 씁니까. 쓰지 말아야 할 때는 언제입니까 |

**사용자가 막히면 노트를 보여주기 전에 힌트 한 단계만** 준다.

### 3. 코드 재구현 (숙련도 3 이상 판정에 필수)

말로만 맞혔으면 숙련도 2까지다. 3 이상은 **노트와 이전 코드를 닫고 다시 구현**해야 한다.

`exercise-forge` 에이전트로 이전과 다른 문제를 받아 풀게 하고, `code-examiner`로 채점한다. **같은 문제를 다시 내지 않는다** — 답을 외운 것인지 개념을 아는지 구별되지 않는다.

### 4. 전이 점검 (숙련도 4~5 판정)

**다른 맥락에서 이 개념을 알아보는가**를 본다.

- 사용자의 실제 코드베이스에서 이 개념이 숨어 있는 지점을 찾게 한다
- 다른 분야의 문제를 주고 "여기 적용 가능한 개념이 뭡니까"라고 묻는다 (개념 이름을 알려주지 않는다)

### 5. 숙련도 갱신과 재스케줄

| 결과 | 조치 |
| --- | --- |
| 막힘 없이 전부 통과 | 숙련도 +1, 간격 다음 칸 |
| 일부 막힘 | 숙련도 유지, 간격 **한 칸 되돌림** |
| 정의부터 막힘 | 숙련도 -1, 간격 1일로 초기화, 해당 스킬로 재학습 |

간격: **1일 → 3일 → 7일 → 16일 → 35일 → 90일**

### 6. 기록

- 노트의 `숙련도`, `최근학습`, `다음복습` 갱신
- **「내가 틀렸던 것」 절에 이번에 막힌 지점을 추가한다** — 지우지 말고 누적한다
- `study/_queue/복습큐.md` 갱신
- `study/_log/<날짜>.md`에 결과 한 줄

## 복습 큐 형식

```markdown
# 복습 큐

| 다음복습 | 주제 | 분야 | 숙련도 | 마지막결과 |
| --- | --- | --- | --- | --- |
| 2026-10-07 | 추이 폐포 | math | 2 | 코드 재구현 실패 |
```

## 주간 점검 (사용자가 요청할 때)

```
## 결론
(이번 주 학습 N건 · 복습 M건 · 숙련도 하락 K건)

## 숙련도 분포
| 분야 | 0~1 | 2~3 | 4~5 |

## 정체 항목
(3회 이상 복습했는데 숙련도가 안 오르는 것 — 접근법을 바꿔야 한다)

## 미처리 큐
(기한 지난 항목)

## 다음 주 제안
```

## 금지

- 질문 전에 노트 내용을 보여주기
- 말로 맞혔다고 숙련도 3 이상 부여
- 이전과 같은 문제로 재평가
- 틀린 것을 "거의 맞았습니다"로 기록
- 기한 지난 큐를 조용히 넘기기
